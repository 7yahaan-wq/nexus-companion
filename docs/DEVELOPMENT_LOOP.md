# 可重复的开发与体验验收流程

本流程适用于 Nexus Companion 的本地开发，约束来自根目录 [AGENTS.md](../AGENTS.md)。它复用现有 Electron、SQLite、Playwright 和 Harness，不启动常驻智能体或付费模型循环。

## 每轮先固定目标和判定条件

1. 核对 Git 状态、版本、Node 和现有结果；不覆盖用户修改。旧报告只是历史证据，没有输入指纹的通过项不可据此跳过。
2. 指定一个独立体验审查者，在 `.test-data/` 的隔离数据库及 Codex 目录里实际操作。记录用户目标、步骤、实际结果、截图和期望行为，区分观察事实与建议。
3. 同时核对少量同类项目的官方源码，记录固定提交链接。只借鉴适合本产品的交互，不复制代码或素材，不因此添加服务或依赖。
4. 每轮选最多两条用户路径，先固定验收矩阵。实施者可以修改产品代码；回归断言不能为迁就实现而削弱。新增需求导致断言确实有误时，先记录理由，再由独立审查者复核。

本轮会话的约束为最多 45 分钟、每个问题最多两次有诊断依据的修改；通过即停止。若预算用完或连续两次没有进展，保留失败证据和下一步，不伪称完成。该约束是当前会话的工作约定，不能当作系统级的常驻调度器。

## 实施、审查和运行分开

- 不同智能体只能编辑各自声明的文件；共享文件依次交接。实现者报告修改和证据，由主智能体检查整合结果。
- 原生 Electron 桌面测试串行运行，避免鼠标拖放、快捷键和焦点互相干扰。审查者先释放实例，下一套件才能启动。
- 先运行最相关的检查，修复时只重跑失败项及其受影响项。已通过的检查在输入未变化时保留，不为消息更新或文档调整重复运行。
- 新版本发布仍需要项目规定的完整 Harness、打包审计和真实便携 EXE 验收。安装器构建不等于执行过安装向导。

## Harness 续跑

默认命令保持完整执行。显式续跑使用：

```powershell
npm run harness -- --full --resume
npm run verify:packaged -- --resume
```

续跑只接受最近 24 小时内、命令参数、执行器、运行环境、相关源码和测试输入指纹匹配的成功证据。构建阶段还要求声明的必要产物存在且哈希一致；打包阶段检查当前二进制和资源。日志缺失、声明的必要产物改变、缓存损坏、失败或超时均不能复用。旧版不带指纹的 JSON 报告不会转换为成功缓存。

报告必须区分 `executed` 和 `reused`，复用时保留原成功时间与证据路径。执行中输入发生变化不能形成可复用的通过记录。失败立即落盘，不能通过跳过失败项完成验收。

运行器最多接受 32 个固定阶段，单步最多 180 秒，共享总期限最多 15 分钟；遇错停止，不自动重试。日志、检查点和缓存只写 `.test-data/`，不进入发布包。具体实现和已验证范围见 [VERIFICATION.md](VERIFICATION.md)；运行器不调用模型，不自行修复产品或修改测试。

## 续接时只读需要的记录

每轮在 `.test-data/iteration-YYYY-MM-DD/` 保留简短状态：目标、基线版本、文件归属、锁定验收、尝试次数、运行中的任务 ID、证据路径、失败原因和下一步。原始输出、截图和测试数据库不提交 Git。恢复时先核对文件、进程和任务状态，不能盲目重发上次操作。中断后保留原尝试计数，并为续接这一轮另记有界预算。

稳定的产品规则和开发入口保存在现有项目文档里；机器路径、临时状态和私人内容不放进全局 skill，也不为每次小改动建立新的知识库。

## 2026-10-23 的两条验收路径

**Agent 恢复路径：** 区分读取中、暂停、目录不可用、可读无会话和筛选无结果。筛选可以一键清除；暂停可以显式启用；连接问题能直接定位设置中的 Codex 区域。显示目录及扫描时间，保留原 tokens、日志和手动查询能力。中英文、浅色和窄窗口均需检查；体验测试不得启动真实官方额度查询。

**日历当下路径：** 在受控的 21:17，进入周/日视图可以看到当前时间；手动滚动后数据刷新不会把用户拉回；重复点击“今天”能重新定位。历史日期没有错误的当前时间线，月视图正常。今天新建日程默认下一个 15 分钟刻度，历史日期仍可从 09:00 起安排；打开表单不会自动保存或改变原记录。

这些条件对应 `tests/agent-recovery.cjs` 和 `tests/calendar-navigation.cjs`。具体执行结果属于当前 [PROJECT_STATUS.md](PROJECT_STATUS.md)，本流程本身不证明它们通过。

实际环境指纹使用传给检查子进程的有效环境。已证实每次工具调用变化的 `CODEX_TOOL_CALL_ID` 从子进程环境移除；PATH、时区、Node/Electron/Playwright 选项及 npm 配置仍参与校验，不按前缀大范围忽略。Vite 的可选 `.env` 文件将存在/缺失状态与内容纳入渲染构建指纹。

## 2026-10-24 第二轮的两条验收路径

**筛选下连续工作：** 项目 P 筛选后从顶部新建默认选 P，保存后可见；进入来源灵感再返回仍保持关键词、项目和排序。无任务或无结果说明原因并可清除筛选；显式快捷记录新任务后清除旧筛选，确保结果可见。筛选只在本次应用会话保留。

**可靠移动：** 原生拖动只提交一次移动请求，不逐张保存整列。基于数据库最新全列排序，隐藏卡相对顺序不变，无重复目标位置。支持直接选择状态；提交中拒绝重叠操作，失败可重试，已提交但读取失败也能用无变化重试恢复。完成时间、专注用时和其他字段受保护，已删除任务不能复活，活动写入失败必须整体回滚。按日期/优先级显示时明确拖动只改状态，同列动作不暗改手动位置。

新增 `tests/task-move.test.cjs` 与 `tests/tasks-flow.cjs`，保留既有回归断言。新桌面路径同时进入源码和打包固定列表。先完成源码、测试和版本变更，再统一运行 `harness -- --full --resume`；版本和源码变化导致旧证据失效时如实执行，不缩小指纹范围。失败后保留结果，只修复有诊断依据的失败项，再续跑。

第二轮独立走查还发现日报未带入已保存的收工回顾、项目详情缺少查看全部任务入口；这两条已进入下述第三轮。临时证据在 `.test-data/ux-review-20261024-round2/`，当前结果见项目状态。

## 2026-10-28 第三轮：回顾可取回、项目任务可找全

独立体验者在隔离配置中复现：回顾已写入 settings，但主页入口只到时间线，日报/剪贴板/实际导出都缺回顾；项目有九个任务，详情只展示五个且没有完整入口。本轮仅解决这两条路径。

固定验收由独立智能体编写 tests/review-navigation.cjs：即时跳转等待保存、失败保留草稿并原入口重试；今日/昨日/无记录日期相互隔离，两种响应乱序都不能提供旧日报；加载/失败时禁用复制导出；完整多行复制等于实际导出；项目 9→编辑较旧任务→空项目 0→新建关联任务 1；首页显式全部与侧栏保留筛选有不同意图。英文浅色 1060px 检查布局，最多两张新截图。

发布清理从 package 后移到 packaged 全部通过之后。先预览精确目标，校验当前与指定回退版本完整文件、哈希和进程占用，再 apply。媒体先审阅、记录结果与路径，确认不属于复用必需证据后删除，并在报告标记“媒体已清理”。保护测试输入、数据库、缓存依赖的日志/输出及用户原有修改；不递归删除目录。每次运行分别报告 executed/reused，不能用文档更新作为重跑理由。

第三轮发布中复现了既有 notes-flow 自动化与编辑框初始化 focus 的竞态：正文 fill 先得到焦点，随后初始标题 focus 将 beforeinput/input 接到标题；SQLite 保存了实际收到的标题值。通过新隔离 profile 的事件轨迹确认后，只为该测试入口等待 ready 和初始标题焦点，不加 sleep、不削弱草稿断言。保留失败日志、只读数据库观察及诊断 trace。随后 --resume 只执行受影响单元/笔记阶段与尚未执行阶段。

清理门禁额外绑定 packaged:agreement 的输出摘要与当前 audit/checksums 完整字节。同版本重打包也必须重新验收，不能将旧的全绿报告配上新包审计。

交付说明更新后可重新运行 finalize-release；其校验和顺序与 verify-release 保持一致，避免仅更新配套文档就改变已验证的 checksum 字节。脚本有改动则续跑受影响单元阶段；二进制、源码和桌面测试未变时复用桌面成功记录。
