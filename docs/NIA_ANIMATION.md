# Nia 动画与立绘（0.4.0 整合，非 idle 美术待验收）

悠闲陪伴的图集、源帧、顺序与时长保持不变。其他七种状态改为各自的 24 张完整画面，分别呈现专注视线、思考、微笑回应、提醒、担忧后安慰、困倦哈欠和庆祝眨眼。用户尚未验收新素材，不能将自动测试通过等同于画风通过。

本页描述从远端 0.3.11 保留到 0.4.0 的播放器和候选素材。只有 `art/nia-classic-frames/idle/` 与 `public/assets/nia/animations/idle.png` 是已被用户接受的动画美术；其他旧面部图集均是被否定的历史材料。保护 `res/Nia.png`、`public/assets/nia/calm.png`、idle 哈希、帧序列 `[0,2,...,22]` 及 700/115 ms 时长，具体约束以根 `AGENTS.md` 为准。

## 素材和播放

原画由内置 imagegen 工具基于已认可的悠闲画面生成。每状态两页，每页 4 列 3 行，共 24 个完整画面，原页 1536×1024。源页、提示词和独立 PNG 位于 `art/nia-state-hires/`。裁切配准脚本是 `scripts/prepare-nia-states.py`；每个输出可以通过 manifest 的 sourceIndex 追溯原格。

只对整张画面做等比缩放和平移，一次从原格采样，不拼脸、不叠图、不光流补帧。透明像素使用预乘 alpha 采样，避免透明区域的隐藏 RGB 污染边缘。输出仍为 6×4 图集，每格 362×362，边缘留白至少 8 像素。定位徽标测量只是整体锚点指标，不能保证头发、脸部和电脑的所有笔触逐像素相同。

运行时一次显示一个格子，无交叉淡化和状态滤镜。普通动作每格 105–160ms，首格 500ms、末格 600ms；一次约 3.4–4.6 秒。工作、思考、困倦循环，开心、提醒、担忧、庆祝播放一次并停留。悠闲继续采用原 12 个偶数格，首格 700ms、其余 115ms。

修复了切换状态时先显示静态末帧再回到首帧的问题；图集预解码后开始计时，切换图片使用独立 DOM key，避免旧图片承接新图集坐标。隐藏窗口、关闭动画和减少动态效果仍可停播。

八张完整立绘源文件位于 `art/nia-portraits/`，运行资源位于 `public/assets/nia/portraits/`。右上角“动画／立绘”将 `avatarDisplay` 保存在本地；Core 与自定义 Avatar Pack 继续支持。0.4.0 增加伙伴栏紧凑偏好，窄窗口使用独立小栏，同时保留显示模式选择。

## 验收

在设置的角色预览中逐一点击八种状态，核对表情、触发条件、首尾接缝和显示大小下的清晰度。检查真实动画，不能仅看原画缩略图。`npm run harness` 检查源文件校验值、独立图集绑定、播放、透明边缘及定位点；`npm run verify` 检查完整桌面行为。0.3.11 的私有源码上传曾获用户授权，但这不代表美术通过验收；后续发布仍按当前任务的实际授权执行。

2026-10-08：整合后的 `harness --full` 已通过，内部 verify 为 21 阶段，包含 35 项单元测试及 16 组桌面套件。0.4.0 打包应用也通过 Nia 及其余六组桌面验收，实际便携 EXE 启动通过。无论工程检查结果如何，七组新动画的用户视觉接受状态仍为待接受。

历史被否定的图集、低分辨率 v2 候选仍为历史材料，不参与播放器。静态立绘未改动，`res/Nia.png` 未改动。
